# عرض توقيت عمل التذكرة مع التاريخ (Display Time with Date)

تهدف هذه الخطة إلى إضافة عرض دقيق وممتاز لتوقيت إنشاء أو عمل التذكرة (Time) بجانب تاريخها (Date) في واجهات عرض التذاكر المختلفة، لتقديم رؤية أوضح وأكثر تفصيلاً للمستخدمين والتقنيين حول التوقيت الفعلي للعمليات.

## Analysis of UI/UX, Gaps, and Risks

### 🎨 UI/UX Design Aesthetics & Specs
لتجنب ازدحام الجدول والحفاظ على الطابع الممتاز (Premium Aesthetic) والسرعة الفائقة لـ Casper POS، سنعتمد نمط التصميم ثنائي الطبقات (Stacked Subtext Design):
1. **الطبقة الأولى (تاريخ التذكرة):** يظهر بخط غامق وواضح باللون الأساسي للنص (`text-slate-900 dark:text-zinc-200`) ليكون المقصد الأول للعين.
2. **الطبقة الثانية (توقيت التذكرة):** يظهر بالخط الأصغر (`text-[10px]`) وبلون رمادي ناعم (`text-zinc-500`) مع **مؤشر دائري نابض ناعم** باللون الفيروزي (`inline-block w-1.5 h-1.5 rounded-full bg-cyan-500 animate-pulse mr-1`) لإعطاء إحساس بالحيوية والنشاط للعمليات الجارية.
3. **تعدد اللغات:** يدعم التوقيت اللغتين العربية والانجليزية بالكامل بالاعتماد على الـ `locale` الحالي للنظام (`ar-EG` للغة العربية و `en-US` للغة الإنجليزية).

```
┌────────────────────────┐
│      ٢٤ مايو ٢٠٢٦      │  <- الخط الأساسي (غامق)
│   🟢 ١٠:٣٠ ص           │  <- خط فرعي أصغر مع مؤشر نابض
└────────────────────────┘
```

### ⚠️ Gaps & Scope Verification
* **فقدان أجزاء الوقت في البيانات (Time Data Gaps):** تم التحقق من حقول قاعدة البيانات وقنوات الـ API. حقل `createdAt` مخزن كـ `DateTime` (ISO String) مما يعني أن التوقيت الكامل (الساعة، الدقيقة، الثانية) محفوظ في الكود ولا توجد حاجة لتعديل جداول قاعدة البيانات أو الـ API endpoints.
* **المرتجع وتحديثات الوقت:** في تبويب المرتجعات، سيتم استخدام وقت آخر إرجاع (`lastReturnedAt`) بدلاً من وقت إنشاء التذكرة الأصلي ليكون التوقيت أكثر دقة، وفي حالة عدم وجود تاريخ مرتجع سيتم الرجوع للوقت الأصلي `createdAt`.

### ⚡ Risks & Mitigation Strategy

| المخاطر (Risks) | التأثير (Impact) | الحلول الوقائية (Mitigation) |
| :--- | :--- | :--- |
| **تعارض الهيدريشن (Hydration Mismatch)** | توقف التطبيق أو ظهور تحذيرات في الكونسول أثناء مطابقة الـ Server والـ Client. | **منعدم تماماً:** الواجهات الثلاث مستضافة بالكامل داخل واجهة `TicketsClientPage.tsx` التي تعتمد فحص `isMounted` مسبقاً قبل عملية الرندرة على المتصفح. |
| **ضيق مساحة الجدول والالتفاف (Cell Wrapping)** | التواء النصوص في الجداول الضيقة وتشويه المظهر الجمالي. | استخدام عرض أدنى محدد للخلية (`min-w-[110px]`) مع نمط `flex flex-col` الرأسي الموفر للمساحة الأفقية. |
| **اختلاف تنسيق التوقيت عبر المتصفحات** | ظهور الوقت بصيغ مختلفة غير موحدة. | تحديد صيغة وقت صارمة عبر خيارات الـ JavaScript (`hour: '2-digit', minute: '2-digit', hour12: true`). |
